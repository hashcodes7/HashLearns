# Releases & Tags

In the context of GitHub and Git, tags and releases are related but distinct concepts used to manage project versions.

![GitHub Releases](https://docs.github.com/assets/cb-22960/mw-1440/images/help/releases/releases-tag-selector.webp)

### The Difference Between Tags and Releases

*   **Git Tags (The Foundation):**
    *   **What they are:** A tag is a feature of Git itself. It acts as a static, immutable pointer to a specific commit in your project's history.
    *   **Purpose:** They are primarily used to mark specific milestones (like a version number, e.g., `v1.0.0`) so you can easily reference that point in time later.
    *   **Types:** 
        *   *Lightweight tags:* A simple pointer to a commit.
        *   *Annotated tags:* Stored as full objects in the Git database, containing metadata like the tagger's name, email, date, and a message.
*   **GitHub Releases (The Enhancement):**
    *   **What they are:** A GitHub-specific feature that "wraps" around a Git tag.
    *   **Purpose:** Releases provide a user-friendly interface for publishing software versions. They allow you to add rich context, such as detailed release notes, changelogs, and binary assets (e.g., compiled `.exe` or `.tar.gz` files) for users to download.

### How to Create Them

#### Creating a Git Tag
You can create a tag locally via the command line and then push it to GitHub:
1.  **Create a lightweight tag:**
    `git tag v1.0.0`
2.  **Create an annotated tag (recommended for releases):**
    `git tag -a v1.0.0 -m "Release version 1.0.0"`
3.  **Push the tag to GitHub:**
    `git push origin v1.0.0` (or `git push origin --tags` to push all tags)

#### Creating a GitHub Release
Once a tag is pushed, you can turn it into a full release on the GitHub website:
1.  Navigate to your repository on GitHub.
2.  Click on the **Releases** tab.
3.  Click **"Draft a new release"**.
4.  In the **"Choose a tag"** dropdown, select the tag you previously pushed.
5.  Add a release title, description/release notes, and upload any binary artifacts if needed.
6.  Click **"Publish release"**.
