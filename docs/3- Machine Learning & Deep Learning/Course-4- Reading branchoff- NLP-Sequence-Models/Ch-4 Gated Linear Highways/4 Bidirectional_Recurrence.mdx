# Bidirectional RNNs: Reading the Future

Up until now, our AI (whether it's a Vanilla RNN, an LSTM, or a GRU) has been reading sentences exactly like a human reads a book: from left to right. 

But sometimes, reading strictly left-to-right is actually a terrible way to understand language.

---

## The "Bank" Problem

Take a look at this sentence, but pretend you are reading it one word at a time:

`"I went to the bank..."`

If the AI stops reading here, what does the word "bank" mean? 
Is it a place where you deposit money? Or is it the muddy edge of a river? It's impossible to know.

Now, look at the rest of the sentence:

`"...to deposit my paycheck."`

Ah! The words at the *end* of the sentence completely change the meaning of a word at the *beginning* of the sentence. 
If our AI reads strictly from left to right, by the time it reaches "paycheck," it has already guessed the wrong meaning for "bank" and its memory is permanently corrupted!

We need a way for the AI to see into the future before it makes a decision about the past.

## Enter the Bi-LSTM (Bidirectional LSTM)

The solution is wonderfully simple. We just use **two** LSTMs at the exact same time!

1. **The Forward LSTM:** Reads the sentence normally, from left to right (`"I -> went -> to -> the -> bank"`).
2. **The Backward LSTM:** Reads the exact same sentence, but starts at the end and reads right to left! (`"paycheck -> my -> deposit -> to -> bank"`).

<div style={{backgroundColor: '#f4f4f4', padding: '10px', borderRadius: '5px'}}>
<strong>The Final Mix:</strong> For every single word in the sentence, we take the memory from the Forward LSTM and the memory from the Backward LSTM, and we just glue them together! 
</div>

Now, when the AI looks at the word "bank", its brain contains the memory of everything that happened *before* it ("I went to the") AND everything that happened *after* it ("to deposit my paycheck"). 

It has absolute, perfect context for every single word!

## The Catch

If Bidirectional LSTMs are so good, why don't we use them for everything? 

Because they require the **entire sentence** to be finished before they can work. 
- If you are translating a PDF document, Bi-LSTMs are perfect because the whole document is already written.
- If you are building a speech-recognition AI for a smart speaker (like Alexa or Siri), you can't use a Bi-LSTM! The AI can't read the end of your sentence because you haven't spoken it yet! It would have to wait in awkward silence for you to finish talking before it could start processing.

## Python Code Example

Here is a runnable PyTorch example showing how a **Bidirectional LSTM** processes the sentence from the lesson. Notice how PyTorch glues the forward and backward hidden states together for each token:

```python r
import torch
import torch.nn as nn

# Set seed for reproducible results
torch.manual_seed(42)

# Sample sentence from the lesson
words = ["I", "went", "to", "the", "bank", "to", "deposit", "my", "paycheck"]
seq_len = len(words)
embedding_dim = 16
hidden_dim = 8

# Simulated word embeddings: shape (batch_size=1, seq_len=9, embedding_dim=16)
inputs = torch.randn(1, seq_len, embedding_dim)

# Define a Bidirectional LSTM (bidirectional=True creates both forward and backward paths)
bilstm = nn.LSTM(
    input_size=embedding_dim,
    hidden_size=hidden_dim,
    batch_first=True,
    bidirectional=True
)

# Forward pass through the entire sequence
# output shape: (batch_size, seq_len, hidden_dim * 2)
output, (h_n, c_n) = bilstm(inputs)

# For every token, output contains [forward_hidden, backward_hidden] glued together
forward_states = output[0, :, :hidden_dim]     # Left-to-right context (past)
backward_states = output[0, :, hidden_dim:]   # Right-to-left context (future)

# Examine the representation for the ambiguous word "bank"
bank_idx = words.index("bank")
bank_combined = output[0, bank_idx]

print(f"Sentence tokens: {words}")
print(f"Output shape (batch, seq_len, hidden_dim * 2): {list(output.shape)}")
print(f"\nContext breakdown for '{words[bank_idx]}' (index {bank_idx}):")
print(f"  - Forward memory (past: 'I went to the bank'):       {forward_states[bank_idx].shape}")
print(f"  - Backward memory (future: 'paycheck ... to bank'): {backward_states[bank_idx].shape}")
print(f"  - Glued representation (full 360-degree context):    {bank_combined.shape}")
```

> [!NOTE]
> Because PyTorch runs both directions over the sequence, the output dimension is doubled (`hidden_dim * 2`). At any index $t$, the state contains both the preceding history and the succeeding context.
