## 1.- Reliability
### <span style="color:#e0313a">1.1 retries</span>
Use **bounded retries with exponential backoff**.

```mermaid
flowchart LR
    A["Request"] --> B{"Error type?"}

    B -->|Transient error| C["Retry"]
    C --> D["Wait 100 ms"]
    D --> E["Attempt 2"]
    E --> F["Wait 200 ms"]
    F --> G["Attempt 3"]
    G --> H["Success"]

    B -->|Permanent error| I["Don't retry"]
    I --> J["Return error"]
```
### <span style="color:#e0313a">1.2 Timeouts</span>

| Main concept                     | set timeout for everything API timeout: 30 sec Retriever timeout: 2 sec LLM timeout: 20 sec                                                                                                                                                                                                                                                                                 |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| fallback models<br />(generation)  | have high quality primary model and low quality secondary model which can scale a lot in case primary model is overloaded                                                                                                                                                                                                                                                   |
| graceful failure<br />(retreival)  | specially important in case <span style="color:#e0313a">retreival</span> side failed this means that generation side will have to handle it. Instead of having a hallucinated answer being generated, generate a fallback.<br /><br />lets say vector db crashed so entire retreival crashed. <br />Retrieval failed -> Don't generate unsupported answer -> Safe response        |
| circuit breakers                 | if multiple services access a dependency which is failing, to prevent cascading failures, use CB, here we open the CB to make the request reroute to other channel, After some time: make it half open, test the request and close it only if the dependency starts working. <br />CB Open state -> dependency wont be used.  reroute<br />CB Closed state -> dep will be used. |
| Bounded Retries<br />(API Failure) | Use **bounded retries with exponential backoff**. ## <span style="color:#e0313a">3 Scalability</span>

| horizontal scaling     | on load dont make single server bigger, add new servers instead                                                                                                                                                  |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| asynchronous ingestion | Let background workers handle the async ingestion process while the RAG can still be used                                                                                                                        |
